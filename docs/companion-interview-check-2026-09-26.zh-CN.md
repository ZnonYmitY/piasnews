## 两类服务错误与候选

### 1. 信息缺口路由与事实引用冲突

纯 mock 复现同一句“有据历史部分＋未知逐字原话”在旧合同下的三种结果：

- `public_fact + actual_facts=true`：200，保留引用。
- `insufficient_current_fact + actual_facts=true`：两次生成后仍校验失败。
- 缺证路由误标 `actual_facts=false`：可以 200，但引用被清空、事实文字仍留下。

候选让一个窄范围的历史部分回答进入完整事实校验：缺证路由、有 KF、声明真实历史事实、无 RM/LIVE、非当前事实/活动请求。guard 和序列化共用同一判定，只规范路由，不改回答或自检标记；未知 ID、当前资料、赛事结果、模式和本地安全边界保护继续生效。缺证回答携带事实引用却声明无事实时，不再静默删引用放行。

真实蒙扎案例仍失败：最终 `insufficient_current_fact / actual_facts=false / temporal_scope=none`，却选中 1 个事实 ID。候选拒绝这个不一致输出；没有保存失败原文，不能推断其具体句子。说明仅修路由不能让模型稳定输出一致合同，**不能宣称已修好该案例**。

### 2. 上游成功状态但最终回答空白

私人原话问题在当前线上和候选都复现：`HTTP 200 / finish_reason=stop / parse:empty_content / repair_count=1`，对外返回 502。候选新增了只含枚举和有界计数的诊断；最终尝试确认为 `choices=1 / content=blank / completion_tokens=104`。

这能确认最终 `message.content` 为空或全空白，而不是本地 DNS 失败；提供商报告的 token 数也不证明存在可用回答。仍不能由这些字段确定上游内部原因。诊断不保存输出文本、提示、聊天、请求头或密钥。没有把推理字段当答案，没有模板补写、额外重试或关闭校验。原有一次修复和共同 45 秒时限保留；诊断增强不等于空输出已修复。
