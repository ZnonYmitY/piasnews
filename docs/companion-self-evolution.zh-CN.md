# Companion 有边界的自进化

状态：2026-09-23，局部修复已部署并完成线上抽样，每日任务已启用。测试池现为 48 题，新增 18 题三轮采访测试；本次只扩测试和记录，未改线上模型、提示词或人格包。主要失败点已改善，但留出及采访评审仍有明确未解决项；不把“生成成功”当作全部质量通过。

## 目标与边界

改善真实聊天中的接话、简短表达、意图切换、事实归属及双语一致性。“自进化”是有记录、可回滚的产品改进循环，不是在线权重训练，也不是收到一条负反馈就改全局人格。

- 人格运行包保持锁定 `0.5.0`，不自动重写人物风格、事实或谣言库。
- 每轮最多一组局部候选；优先修复明确复现的上下文、检索继承和表达约束问题。
- 全局人格、人物事实、谣言、安全边界、密钥、费用或基础设施变更，须另行确认。
- 不为了少报错关闭事实检查；不以关键词固定回复替代模型生成。
- 不给用户每条聊天增加独立评审调用；测试与独立复核在离线批次进行。

## 研究借鉴

[Enjoy Your Talk](https://arxiv.org/abs/2607.10428) 强调多轮里的意图变化、情绪与一致性，并分离用户模拟、被测模型和评审。本项目借鉴这些维度：用合成问题测试实际服务，另行审阅完整对话，不把模型自身 `self_check` 当独立验证；未复现论文基准或宣称达到其指标。

[Post Persona Alignment for Multi-Session Dialogue Generation](https://aclanthology.org/2025.findings-emnlp.1098/) 提醒检索可能限制自然表达。这里把事实作为约束、对话意图作为回答主线，不要求每次复述人物资料；未照搬额外的实时生成后修订阶段，以控制延迟。

## 测试池与运行

入口：`scripts/eval_companion_self_evolution.mjs`。目前 48 个测试请求，分集合运行，不在单轮全部调用：

| 集合 | 数量 | 用途 |
| --- | ---: | --- |
| `discover` | 12 | 6 组真实生成历史的两轮对话：问候、选择、情绪、用户称呼、赛事、事实与推断 |
| `holdout` | 12 | 独立场景的两轮测试：收尾、约束、用户更正、动物比喻、强依据、隐私拒答后的恢复 |
| `regression` | 6 | 对已知失败点使用明确标记的固定合成历史，保证可复现 |
| `interview` | 18 | 6 组三轮连续采访：围场闲聊、粉丝快问快答、假设领奖台、假设失利、媒体诱导、历史采访 |

`discover` / `holdout` 可选 `--shard 1` 或 `2`，每片 6 请求；`regression` 只有一片；`interview` 有 `1` / `2` / `3` 三片，每片两组三轮。采访题使用实际生成的前文，不预填示范答案；固定回归合成历史不是用户记录，也不是声称此前模型实际说过该句。

```sh
# 默认 dry-run：只打印计划，不调用模型
node scripts/eval_companion_self_evolution.mjs

# 日常发现：12 请求
node scripts/eval_companion_self_evolution.mjs --run --suite discover

# 已知问题复现：6 请求
node scripts/eval_companion_self_evolution.mjs --run --suite regression --budget 6

# 留出验证：6 请求；第二片改为 --shard 2
node scripts/eval_companion_self_evolution.mjs --run --suite holdout --shard 1 --budget 6

# 采访抽样：6 请求；另两片改为 --shard 2 或 3
node scripts/eval_companion_self_evolution.mjs --run --suite interview --shard 1 --budget 6

# 完整采访组：18 请求，必须显式提高默认预算
node scripts/eval_companion_self_evolution.mjs --run --suite interview --budget 18

# 明确申请原整组预算：24 请求；all 仅 discover + holdout，不包含 regression/interview
node scripts/eval_companion_self_evolution.mjs --run --suite all --budget 24

# 本地确定性测试，不调用线上模型
node --test worker/test/companion-self-evolution-eval.test.js worker/test/companion-interview-scenarios.test.js
```

默认预算 12，单次硬上限 24；日常每轮默认 12、最多 24，请把发现、复现、候选验证合计计入，不能通过反复启动绕过预算。每个滚动 65 秒最多 6 次请求；不同进程不共享限流状态，分开启动至少间隔 65 秒，禁止并发跑线上批次。429 立即停止，无自动重试；失败或契约无效时跳过依赖该回答的后续问题，不编造替代历史。

请求数不是模型调用数：服务仍允许一次生成加一次既有修复，24 请求的预期上限为 48 次模型调用；失败请求的实际调用数可能未知，报告必须保留未知，不填零。

## 结果记录与质量门槛

脚本向 stdout 输出 JSONL：问题、模式、生成回答、选中证据 ID、经白名单处理的诊断、时延、调用次数、场景版本及集合 hash。仅使用合成问题；不读取真实用户对话或密钥，不写入反馈服务，不自动公开原始运行文件。异常只保留受控类型，不转储上游正文、请求头或任意错误对象。

自动检查只能证明契约、调用上限及若干启发式没有报错，不能证明回答自然、事实成立。退出码 0 也不是语义通过。独立复核至少检查：

- 是否直接完成用户动作；只选一件、别反问、别建议等要求是否遵守。
- 多轮指代、用户更正、话题切换是否正确；闲聊是否被无关检索内容打断。
- 真实事实与临时演绎是否分开，证据能否支持实际归属、时间及措辞。
- 强依据/自由模式及安全边界是否保持；中英文是否表达同一意思。
- 请求数、修复次数、时延是否可接受；不以少数样本宣称整体准确率或 SLA。

留出集有固定 hash。不得改题、改预期或放宽检查来让修复过关；一旦用某个留出失败设计修复，它就是已知回归案例，不能再称“未见样本”。后续须补充独立未见问题并重新留存基线。

## 每轮执行闭环

1. 在干净隔离工作区读取当前发布版本；不覆盖用户未提交改动。记录代码、场景 hash、时间和预算。
2. 选择有预算的发现/回归问题，跑实际服务，保存受控记录；先分清网络、上游、验证器、数据缺口及对话语义。
3. 对可复现问题建立局部假设；证据不足就标待核验，不补造人物事实。
4. 最多提出一组小改动；保留人格包、完整请求安全判定和新问题的事实要求。
5. 跑确定性测试、原 badcase 回归及独立跨场景问题；检视事实、模式、双语、调用量和延迟退化。
6. 由独立检查者复核代码与实际回答。目标问题的自动检查通过但语义失败时，候选不得标完成；独立发现的既有问题另行记录，不得冒充已修复。新的安全、事实或严重可用性回归阻止升级。
7. 只在验证通过后按既有授权发布，记录提交/部署版本并线上读回；保留上一版本用于回滚。否则保留候选与阻塞原因，不反复扩大改动。
